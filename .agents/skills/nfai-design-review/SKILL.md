# NFAI design review

1. Identify the audience, task, primary action, brand constraints, and existing design language from the brief or current interface.
2. Define hierarchy and responsive layout before styling. Use consistent spacing and type scales, legible line lengths, purposeful visuals, and a distinct visual identity grounded in the brief.
3. Design states for keyboard focus, loading, errors, empty results, and successful actions when relevant. Keep motion short and functional. Respect reduced-motion preferences.
4. Review the result at mobile and desktop widths. Exercise the actual primary action, keyboard navigation, visible focus, contrast, zoom or reflow, and overflow. Inspect screenshots or browser snapshots when available. Use a first-party design connector only after the user selects the target file and grants access.
5. Report concrete defects with the location, evidence, and correction. Mark checks that could not run. When evidence and a claimed result conflict, preserve the evidence and revise the result.

Use the project's existing tokens and UI components where they fit. Keep reference designs as inspiration and use original content and assets. For accessibility details, consult [WCAG 2.2](https://www.w3.org/TR/WCAG22/).
