# Параллельный Claude и учёт квот

28 октября · [Arena, 00:07–00:34](https://www.youtube.com/watch?v=LpCrU6uJ7po) · [Лимиты, 00:11–00:42](https://www.youtube.com/watch?v=Xz8AJZV2ZaM) · [Шлюзы Claude Code](https://code.claude.com/docs/en/llm-gateway) · [Лимиты Groq](https://console.groq.com/docs/rate-limits)

Из Arena годится независимая проверка по заранее заданным критериям. Число запусков само по себе ничего не говорит о качестве. Для точного ответа в первую очередь достаточно проверяемого эталона, а для независимых задач — ограниченной очереди. Тест NFAI запустил два реальных процесса Claude Code 2.1.327 с разными рабочими папками через один OmniRoute 3.8.53, Qwen3-4B и один слот llama.cpp. Шлюз вернул HTTP 200, процессы вернули ожидаемые 42 и 33. Их времена составили 7,531 и 4,307 с. Единого последовательного эталона в этом прогоне не было, поэтому ускорение не заявляется.

Токены из двух ответов CLI, в порядке input / cache read / output: 226 / 35 / 3 и 259 / 1 / 3. Они относятся к локальным задачам. Цифры из ролика о бесплатных токенах повторяют заявления о [FreeLLMAPI](02-free-llm-api.md) и [OmniRoute](01-claude-code-addons.md), не показывая баланс NFAI. GPT-OSS-120B остаётся кандидатом для проверки инструментальных вызовов при наличии подтверждённого разрешённого бесплатного доступа. Облачный маршрут не проходил живой тест.
