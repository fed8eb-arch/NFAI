## Условия

1. **Имя секрета.** `LEAD_WEBHOOK_SECRET` заменяет `NETLIFY_FORMS_WEBHOOK_SECRET`. Причина: сайт использует путь `/api/contact` → Resend, а не Netlify Forms (см. `w3-lead-path.md`, коммит `4f9f232`). Имя можно задавать в коде через конфигурацию, но значение по умолчанию и README используют **именно это** имя.

2. **Хранение.** Только через keydrop, в `~/secrets/agency-llm.env`; права файла 600, каталога 700, владелец `box` (базовая проверка 2026-11-23: соответствует требованиям). Значение — случайное, не короче 32 байт (например, `secrets.token_urlsafe(32)`), генерируется на боксе без вывода на экран, в чат или в аргументы команд. Доказательство наличия — только вывод `keydrop.py check`: имя, длина, префикс sha256.

3. **Кто читает.** Только процесс воркера, запущенный от пользователя `box`, при старте из окружения по имени (`set -a; . ~/secrets/agency-llm.env; set +a`), а также синтетический тестовый клиент — тоже из окружения. Копий нет в других файлах, в каталоге воркера, в unit-файлах systemd и в `.env` в репозитории.

4. **Сеть.** Воркер слушает только `127.0.0.1`; публичного URL нет. Любой публичный входящий путь требует отдельного согласования Службы внутренней безопасности и Директора (изменение сайта — только с согласия Основателя).

5. **Аутентификация.** Секрет проверяется на каждом запросе через `hmac.compare_digest` (сравнение за постоянное время). Отсутствие секрета или неверное значение — ответ 401 без подробностей и без эха секрета.

6. **Журналы.** В логах нет секрета, нет заголовков `Authorization` и `X-*-Secret`, нет сырого тела запроса. Журнал только локальный, не в git. Клиентские PII не попадают в репозиторий и не отправляются в Gemini free-tier. Тесты — только на синтетических данных. Файл `route.ts` не изменяется.

7. **Ротация.** Немедленно при любом подозрении на утечку; обязательно до первого живого хука (тестовый секрет не должен совпадать с боевым); каждые 90 дней; и в день, когда агент или подрядчик теряет доступ. Порядок: новое значение через keydrop, перезапуск воркера, `keydrop check` (новый префикс sha256) и запись в отчёте.

8. **`HUBSPOT_API_KEY` (W1).** Те же правила хранения, круга читателей, журналирования и ротации. Используется только для записи в HubSpot после завершения W1.

9. **Рекомендация, не блокер.** Добавить в `.gitignore` строки `*.env`, `!.env.example` и `secrets/`.
