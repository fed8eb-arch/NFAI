## Куда сейчас уходят заявки

Это не Netlify Forms.

1. **Браузер.** `components/project-inquiry-form.tsx` (строки 36–40) делает `fetch("/api/contact", { method: "POST", headers: { "Content-Type": "application/json" }, … })`. В теге формы (`method="post"`, строка 75) нет `action`, нет атрибутов `data-netlify` / `netlify` и нет поля `form-name`. Поля: `name`, `company`, `email`, `location`, `phase`, `message`; honeypot `website` (строка 94); плюс `requestId` (UUID v4). Без JavaScript заявка не уходит (`noscript`, строка 76). То же видно в публичном HTML и в бандле `/_next/static/chunks/app/(commercial)/contact/page-9327b8a7cbff4c9f.js` (наблюдение 23.11.2026, около 20:13 EST, America/New_York).

2. **Сервер.** Единственный обработчик — Next.js App Router, файл `app/api/contact/route.ts`, экспортируется только `POST` (строка 5). Это не функция из каталога `netlify/functions` (такого каталога в репозитории нет). В `netlify.toml` нет настройки Forms; комментарий указывает сборку Next.js через OpenNext на Netlify.

3. **Проверки до отправки.** Origin (строки 10–12), JSON (строки 13–15), honeypot и формат `requestId` (строки 44–47), валидация полей (строки 49–63; лимиты в `lib/project-inquiry.ts`). Edge-функция `netlify/edge-functions/api-guard.js` на пути `/api/*` проверяет same-origin и rate limit, затем вызывает `context.next()`: заявки она не сохраняет и не пересылает.

4. **Доставка — почтовый API Resend, не база и не вебхук агентства.** Если заданы переменные окружения `RESEND_API_KEY`, `RESEND_FROM_EMAIL` и `PROJECT_INQUIRY_EMAIL` (строки 64–68; те же имена в `.env.example`, строки 12–14), обработчик делает POST на `https://api.resend.com/emails` (строки 70–90). Письмо уходит на адрес из `PROJECT_INQUIRY_EMAIL`, `reply_to` — email заявителя. При успехе клиенту возвращается `{ sent: true }` (строка 91). Если любая из трёх переменных не задана — HTTP 503, заявка «не отправлена» (строки 67–68). В базу этот обработчик ничего не пишет. Содержимое заявки в лог не пишется (строка 93). Другого стороннего вебхука в этом файле нет.

Публичная политика (`/privacy`) говорит, что при настроенной доставке Resend пересылает заявку в inbox продаж WireReady. Это совпадает с кодом.

**Не проверено** (нет доступа к Netlify, форму не отправляли): заданы ли `RESEND_API_KEY`, `RESEND_FROM_EMAIL` и `PROJECT_INQUIRY_EMAIL` на продакшене. Если нет, живые заявки получают 503 и никуда не уходят.

## Куда должен встать воркер на боксе (предложение)

Не к Netlify Forms: в коде подписываться не на что.

Воркер должен принимать JSON в формате тела `/api/contact` (поля формы + `requestId` + пустой `website`). Живое подключение — только после успешной отправки в Resend (`route.ts`, после `response.ok` на строке 91): обработчик шлёт тот же JSON на URL воркера с общим секретом. Имя секрета лучше согласовать со Службой внутренней безопасности: в брифе указано `NETLIFY_FORMS_WEBHOOK_SECRET`, но Forms не используется. Это изменение сайта: сначала превью, в продакшен — только с согласия Основателя. В этом шаге репозиторий `wireready` не менялся.

До этого решения воркер тестировать на синтетическом payload того же формата. Запись в HubSpot — после W1.
