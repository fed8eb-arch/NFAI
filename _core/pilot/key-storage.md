# План хранения ключей API (фаза B)
Версия: v1.0 | Дата: 2026-11-17 ET | Автор: Разработчик интеграций | Статус: УТВЕРЖДЁН Директором 2026-11-17 13:57 ET
В этом файле только ИМЕНА переменных. Значения ключей не пишутся сюда, в чат, отчёты, код, команды shell и скриншоты.

## 1. Где хранится и права доступа
- Один файл: `~/secrets/agency-llm.env` (`/home/box/secrets/agency-llm.env`), формат `ИМЯ=значение`, по строке на ключ.
- Права: каталог `~/secrets` = 700, файл = 600 (владелец `box`). Каталог вне `/workspace` (там всё читаемо всем и попадает в общие материалы).
- Честное ограничение: все агенты на общем компьютере работают под одним пользователем `box`, поэтому права файла защищают от посторонних процессов/пользователей, но не разделяют агентов между собой. Разделение — по правилу: пишет только Директор (или его исполнитель), читают только роутер и Разработчик интеграций, и только через скрипты ниже (никто не делает `cat` файла).
- Файл не копируется, не бэкапится, не коммитится. Потеря файла не страшна: ключ перевыпускается в консоли провайдера.

Имена переменных (по очереди регистраций `signup-queue.md`):
`POE_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `ZAI_API_KEY`, `DASHSCOPE_API_KEY` (+ `DASHSCOPE_WORKSPACE_ID`, не секрет, но храним рядом), `HEYGEN_API_KEY`, `MAGICHOUR_API_KEY`, `VIGGLE_API_KEY`, `MISTRAL_API_KEY`, `PERPLEXITY_API_KEY`; для роутера `LITELLM_MASTER_KEY`. Новое имя = `<ПРОВАЙДЕР>_API_KEY`, верхний регистр.

## 2. Как исполнитель кладёт ключ из браузера (без чата и логов; xclip не нужен)
Инструмент: `/workspace/pilot/tools/keydrop.py` — маленькая локальная форма на `127.0.0.1:8765` (только этот компьютер, не в интернет). Проверено 17.11 на фиктивном значении: файл создаётся с правами 600, наружу выводится только имя, длина и 8 символов sha256.
1. Запустить в фоне: `python3 /workspace/pilot/tools/keydrop.py serve` (команда без ключа).
2. В браузере на странице ключей провайдера нажать «Copy» у созданного ключа (не выделять вручную, не увеличивать, не делать скриншот этого экрана для отчёта).
3. В той же вкладке/новой вкладке открыть `http://127.0.0.1:8765`, выбрать имя (например `POE_API_KEY`), вставить ключ (Ctrl+V) в поле типа password (видны только точки), нажать «Сохранить».
4. Страница ответит: «Сохранено: POE_API_KEY (новый), len=…, sha256=…». Это и есть доказательство для отчёта/скриншота (значения нет).
5. Остановить форму (Ctrl+C / завершить процесс). Закрыть страницу ключей провайдера.
Почему так: ключ не набирается в shell (не попадает в историю и транскрипты), не проходит через чат, сервер не пишет логи запросов. Остаточный риск: исполнитель видит ключ на экране провайдера в момент создания — это неизбежно; поэтому скриншоты этого экрана не прикладываются никуда.

## 3. Как роутер читает ключ
- В `config.yaml` LiteLLM только ссылки: `api_key: "os.environ/GROQ_API_KEY"` (документированный синтаксис, https://docs.litellm.ai/docs/proxy/configs).
- Запуск роутера загружает файл в окружение процесса, не печатая его:
  `set -a; . ~/secrets/agency-llm.env; set +a; litellm --config /workspace/pilot/router/config.yaml --port 4000`
  (или для Docker: `--env-file ~/secrets/agency-llm.env`).
- Агенты получают не ключи провайдеров, а свой виртуальный ключ роутера (см. `router-design.md` §6); его тоже кладут через keydrop под именем `AGENCY_ROUTER_KEY_<АГЕНТ>`.

## 4. Как проверить, что ключ есть, не показывая его
`python3 /workspace/pilot/tools/keydrop.py check` → по каждому имени: `present, len=N, sha256=xxxxxxxx`. Сверка «тот ли ключ» — по sha256-префиксу, записанному в отчёте при сохранении. Рабочесть ключа проверяется только тестовым вызовом (по сигналу Оркестратора), в логе — модель, задержка, код ответа, без значения.

## 5. Замена и отзыв
- Замена (ротация): создать новый ключ в консоли провайдера → сохранить через keydrop под тем же именем (ответ «заменён», новый sha256) → перезапустить роутер → тестовый вызов → удалить старый ключ в консоли провайдера.
- Отзыв (утечка или отказ от сервиса): сначала удалить/отозвать ключ в консоли провайдера (это главное — локальное удаление не отменяет ключ) → `python3 /workspace/pilot/tools/keydrop.py remove NAME` → перезапустить роутер → отметить в `status.md` (без значения).
- Подозрение на утечку (ключ попал в чат, файл, скриншот): немедленно отзыв по пункту выше и сообщение Оркестратору; файл/сообщение с ключом удалить.

## 6. Чего не делаем
Не пишем ключи в `/workspace`, в `.env` проектов, в `config.yaml`, в аргументы команд, в чат, в Vault-заметки агентов, в скриншоты. Не храним старые ключи. Не передаём ключи провайдеров агентам.
