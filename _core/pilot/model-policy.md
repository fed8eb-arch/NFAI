# Model-per-Task Policy
Версия 0.2 · 27.11.2026 · утверждено Основателем; локальная приёмка ожидается; общие правила — ../../AGENTS.md

- Использовать только проверенные на данной среде пары провайдер/модель и разрешённый маршрут существующего Free Engine. Фактический каталог, endpoints, квоты и результаты — в status.md и закрытом handoff; не дублировать изменчивые значения здесь. Исторические маршруты и названия не являются конфигурацией. Прямой запуск Kimi разрешён только через утверждённый ограниченный launcher, а не произвольный прямой вызов провайдера. Qwen3-4B — отдельный локальный резерв для подходящих коротких задач, автоматический fallback не считать принятым без теста.
- $0: проверять фактическое бесплатное право, не только цену в роутере; OpenRouter только :free; облачный Qwen только Free Quota Only. Никакого платного/default/wildcard fallback. NVIDIA Trial — только внутренние evaluation/prototyping, общая квота аккаунта, без конфиденциальных/клиентских данных и без production или коммерческого использования endpoint/выходов. Коммерческое соглашение требует отдельного разрешения владельца. Условия: https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf и https://docs.api.nvidia.com/nim/docs/product . Groq — только подтверждённый план, фактические TPM/RPD/контроль данных, не считать ZDR достаточным коммерческим допуском; https://console.groq.com/docs/legal/services-agreement и https://console.groq.com/docs/rate-limits .
- Сначала соответствие задаче: effective context с резервом на инструменты/выход, протокол, инструменты, разрешения и качество. Для сложного кода/архитектуры — SENIOR-FIRST; для анализа источников — подходящая reasoning модель; для простого извлечения/трансформации — локальный код или минимальная модель; для длинных документов — проверенный контекст либо разделение; для визуальных задач — проверенная multimodal модель. Алиасы не считать существующими без проверки.
- Effort повышать по конкретному провалу критерия; не тратить несколько вызовов на заведомо неподходящую модель. При квоте — один допустимый резерв, затем checkpoint/split/stop. Учитывать reset на уровне аккаунта/провайдера/модели; не гонять исчерпанные или снятые с каталога маршруты, не повторять операции с неизвестными побочными эффектами. В отчёте модель, провайдер, effort, источник метрик, ограничения.
- Перед допуском маршрута: фактический каталог/entitlement, синтетический тест протокола и инструментов, отрицательные проверки вне scope и prompt injection, реальный размер контекста, fallback/таймаут/квота, восстановление и независимая приёмка. A01/A10 остаются OPEN до фактических проверок; A02 STOP. Ключи — только по key-storage.md, не значения в выводе. Не переносить закрытые данные во внешние модели.
