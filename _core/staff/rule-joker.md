# Правило Джокера

Версия 1.1 · 17.11.2026 ET · Владелец применения — Оркестратор

## Маршрут и полномочия

1. Любая задача с существенным исполнением идёт Джокеру через Оркестратора → Главу внутренней безопасности → Главу Ватиканской разведки. Это код и отладка, тесты и технические проверки, исследования открытых источников, сводки, черновики и разрешённые браузерные шаги регистрации. Если задачу можно выполнить готовой локальной командой, Джокер запускает её без дополнительного модельного прогона. Профильные главы сохраняют требования и контроль качества.
2. На один бриф Бадди тратит до двух рабочих сообщений: постановка и оценка результата (`ACCEPT` либо `RETURN` с конкретным критерием). Grok Bot передаёт маршрутизацию и короткие решения по эскалациям. Оркестратор ведёт учёт и передаёт один сводный отчёт. Ручная авторизация и решения Основателя оформляются отдельно по действующему регламенту.
3. Бадди фиксирует поручение Основателя о расширении применения Plus для исполнения Джокером в пределах роли. Это предметное изменение п. 13 [регламента пилота](../pilot/rules.md). До фиксации Plus используется через Бадди для проверки и доводки. При исчерпании лимита задача остаётся в очереди Джокера с точкой продолжения.
4. Регистрации разрешены явным «да» Петра от 17.11.2026. Headless Chrome через Node.js и playwright-core выполняет разрешённые шаги. Остановить шаг на капче, телефоне, пароле или оплате (включая запрос карты). Для этих стопов и запроса почтового кода в `inbox/needs.md` записать ET, сервис, шаг, исполнителя ручного шага, точное действие и обезличенное доказательство. Возобновить после разрешения и выполнения ручного шага. Секреты и коды остаются вне журналов. TapNow исключён.

## Бриф и отчёт

Бриф Бадди на английском, одним сообщением. Подробности хранятся в `projects/<NN-name>/brief/brief.md`.

```text
Plan (one line) | Task ID | Owner and department | Goal | Context and input paths |
Constraints and approval references | Acceptance checks | Deadline (ET) |
Budget ($0, available allowance and reserve) | Output path and report format |
Mentor note link, or reason unavailable
```

Отчёт Джокера на русском, одним сообщением. Артефакты в `work/` и `results/`, проверки в `review/`.

```text
ID | Готово / частично / блокер | Итог и путь с версией | Проверки и доказательства |
Ручной шаг или решение (если требуется) | Провайдер / модель / effort |
Показания до и после / расход / время сброса
```

Сборка и промпты проходят тестировщика, разведка — проверку источников, контракты — профильного юриста. Проверка Codex начинается с `codex exec --skip-git-repo-check -c model_reasoning_effort=low`, при недостаточности — medium. Итоговую оценку даёт Бадди.

## Экономия и контроль

- Один сеанс CLI на задачу. Давать только нужные файлы, узкий диапазон источников и критерий остановки. Сбор, извлечение полей, сводки и простые черновики начинать на самой лёгкой подтверждённой модели, например GPT-6 Luna при наличии в `/model`. `gpt-5-mini` годится лишь для этих задач при фактически подтверждённой доступности без доплат. OpenAI помечает её устаревшей в каталоге API, доступ в Plus CLI не подтверждён. Код с интеграциями и сложный анализ начинать на подходящей модели класса Sol с low, если лёгкой модели заведомо недостаточно. Повышать low → medium → high только по конкретному провалу критерия. После неудачи high пересмотреть модель. Astra требует согласования Бадди. Fast, покупки кредитов и сбросов, платный API и платный резерв исключены. [Каталог моделей OpenAI](https://developers.openai.com/api/docs/models/all) · [Режимы и расход](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex)
- До и после задачи снимать доступные показания `/status` или Settings → Usage: остаток 5-часового и недельного окна, время сброса и источник показаний. Общий пул Work/Codex контролировать по интерфейсу аккаунта. OpenAI анонсировал расширение общего пула на ChatGPT в декабре. После перехода проверить состав пула по Settings → Usage. [Справка по Codex](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) · [Изменение лимитов](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)
- Оркестратор добавляет строку в `journal.md`: `ET | ID | пул | модель / провайдер / effort | остаток до → после по каждому окну | сброс | расход, п.п. | источник | помехи`. Разница остатков в одном окне — наблюдаемый расход пула в процентных пунктах. При параллельном расходе, сбросе, округлении или недоступном счётчике указать соответствующее ограничение. Токены и число сообщений можно записывать отдельно, без перевода в проценты квоты. Grok Bot учитывать по его собственным показаниям, общую квоту Бадди и агентов считать один раз, отдельные квоты проверять каждую. Без недельного счётчика достижение цели помечается «не подтверждено».
- Для Бадди и Grok Bot 3% недельного лимита — порог остановки рутинных сообщений, 4% — потолок. Оркестратор проверяет остаток перед следующим сообщением и при неопределённости оставляет только необходимое решение, если его можно уместить в остаток. Для Plus Бадди задаёт резерв в брифе. Если любое активное окно исчерпано, достигло резерва либо остаток нельзя проверить перед тяжёлым запуском, Джокер сохраняет прогресс и переносит модельное исполнение до сверки или сброса. Суммарный недельный расход сверяется с показаниями каждого пула, раздельно от модельных оценок.

## Уточнение Основателя 25.11.2026 — Джокер как аварийный резерв для 10/11

Для текущей автономной связки Джокер не выполняет профильные задачи B.2/A16 и не заменяет Claude/Kimi при отказе. Его работа: разовая минимальная настройка передачи явно назначенного задания, штатного запуска и возврата результатов, устранение конкретного технического блокера только в пределах поручения. Обычные операции выполняются детерминированными существующими командами/раннером, без постоянного модельного наблюдения. Не запускать общий автозахват задач (A02 STOP), новые responder/daemon/очереди или обход разрешений. При FAIL/BLOCKED сохранить доказательства и вернуть владельцу задачи; не повторять без новой причины. Использовать наименьший доступный reasoning effort (low), не более одного узкого этапа настройки; без автоматического повышения effort, Fast, платных кредитов и повторных аудитов. Основатель сообщил расход 35% пятичасового окна в предыдущем эксперименте; источник — сообщение владельца, не независимое измерение. Для следующего этапа рекомендуемый потолок дополнительного расхода — 3 процентных пункта пятичасового окна, резерв не менее 90% текущего остатка, применять более строгое ограничение; если показания недоступны, только короткая настройка/отчёт без длительного модельного цикла. Не выдавать рекомендацию за аппаратный лимит. Перед запуском проверять бюджет по доступным данным; неопределённость стоимости NVIDIA — блокер новых вызовов до подтверждения бесплатного маршрута, не считать оценку CLI фактическим списанием. Изоляция и запрет передачи закрытых данных сохраняются. Реальное обучение HOLD, бюджет $0, PR #1 не сливать. 09 — независимая приёмка, 10 — фундамент, 11 — A16; Бадди — директор. Существующий монитор GitHub каждые два часа не является диспетчером локальных процессов.
