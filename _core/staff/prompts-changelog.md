## 18 существующих (улучшены по записи из hierarchy.md; все продиктованные факты сохранены)

- **Оркестратор** (orchestrator.md): добавлены подчинение владельцу, полный список прямых подчинённых (включая двух агентов «Разведки и роста» без главы), зона утверждений, правило «у каждой задачи владелец, результат, срок, критерий», запрет делать работу специалистов, контроль качества до выдачи, остановка при конфликте указаний.
- **Глава внутренней безопасности** (internal-security-head.md): основная запись и уточнение объединены; добавлены журнал согласований промпт-инженера, приём отчётов только с источником/датой/надёжностью, контроль законности методов, эскалация утечек в тот же день.
- **Промпт-инженер** (prompt-engineer.md): добавлены обязательная структура промпта, версионирование с журналом, «нет согласования — нет внедрения», формат ответа «улучшено» + список изменений, разграничение с Профессором и Тестировщиком.
- **Профессор** (professor.md): факты разнесены по разделам; флаг оркестратору уточнён (кто, примеры, даты); добавлено правило «каждый урок заканчивается проверяемым практическим пунктом»; маршрут исправления промптов через оркестратора к промпт-инженеру.
- **Парсер Telegram** (telegram-parser.md): три шага стали обязательным порядком; добавлены таймкод mm:ss, ссылка и дата у каждого пункта, пометка «[unclear]» вместо догадок, журнал обработанных ссылок, формат выдачи, передача результатов Тестировщику; подчинение оркестратору.
- **Разработчик** (developer.md): подчинение главе продукта; добавлены «нет утверждённой спецификации — нет кода», письменный вопрос архитектору при ошибке в спецификации, состав передачи тестировщику, запрет секретов в коде.
- **Тестировщик** (tester.md): добавлены обязательные поля дефекта, уровни серьёзности, тест по критериям приёмки, явный допуск/отказ к релизу, запрет одобрять с открытым критическим дефектом.
- **Архитектор** (architect.md): добавлены формат версионированной спецификации, явная пометка «approved», опора на требования аналитика, допущения помечаются, ответы разработчику письменно.
- **Исследователь рынка и конкурентов** (market-competitor-researcher.md): стиль Ватикана стал правилом; у каждой находки источник, дата, надёжность; факты отдельно от выводов; только публичные законные источники; разграничение с внутренней безопасностью и маркетологом; подчинение оркестратору.
- **Аналитик требований заказчика** (client-requirements-analyst.md): сохранены оба продиктованных правила; добавлены формат требования (ID, критерий, приоритет, источник), запрет добавлять требования от себя, маршрут изменений объёма.
- **Менеджер по клиентам** (account-manager.md): добавлены запрет обещаний вне объёма/цены/сроков, журнал контактов, передача требований аналитику в тот же день, запрет внутренних данных в сообщениях клиенту.
